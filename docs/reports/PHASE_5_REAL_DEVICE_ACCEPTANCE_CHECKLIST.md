## 0. 铁律（先读，避免误判 FAIL）

1. **M1/M2 只能在真机执行**：AVD 无 zh-CN 离线识别包、无真人声输入，不能代替（Step 1 报告 §17.2/§17.3）。
2. **授权后必须重启 App 才恢复语音**：进程内 `isAvailable` 在权限拒绝/缺失的 listenOnce 尝试后已被拉低且**不自动恢复**（裁决 D5 设计语义，诚实降级；Step 1 报告 §17.1）。M1 的授权步骤后有一次重启——这是设计行为，不是 bug。
3. **窗口时长默认 4000ms**（guard 300ms 后开窗）：别名必须在窗口倒计时内说完。
4. **Timeout ≠ 识别失败**：用户未说话/无有效输入导致的窗口超时，M2 统计口径中**不计入**分母。
5. **TTS/音频播放期间识别器是关闭的**（FR-12/TC-AE-06）：播放中说任何内容无反应是**正确行为**；语音命令只在 CommandWindow（窗口提示「🎤 请说『会了』」显示时）有效。
6. 别名固定为代码常量：**会了 / 记住了 / 掌握了**（裁决 D4；用户可编辑别名归 Phase 8）。
7. ~~**坏服务机型（vivo）每次冷启动后的第一个窗口，前 ~1500ms 无活动监听**~~ **已修复（2026-09-16，commit `a9c4fec`）**：主备引擎互换后 Vosk 为主引擎（窗口前已 prewarm、响应≈0ms），首窗开窗即可说命令，无盲区。本条保留为历史记录。
8. **切后台再回来 = 会话自动暂停（设计行为，非故障）**：切走 app → 音频焦点丢失 → 自动暂停（安全设计：焦点回归不自动外放，TC-AE-16）；回来后界面显示「已暂停」+「继续」按钮，**点继续恢复播放后语音命令才重新有效**（暂停态无命令窗口）。M2 统计中此类暂停后未点继续就说话 = 不计分母。
9. **vivo 的 `adb install -r` 会重置 RECORD_AUDIO 授权**（2026-09-17 实测）：每次 adb 装包后的首次启动预期走「授权条 → 允许 → 重启 App」一轮（与铁律 2 同流程），非回归。

## M2 — 识别率（出口门禁：≥ 90%）

**目标**：安静环境、明确发音下，三个别名（会了/记住了/掌握了）的命令命中率（ROADMAP Phase 5 出口）。

**口径**：

- **总说命令次数** = 用户在窗口内**有意说出某个别名一次**的次数（建议每个别名 ≥ 10 次，合计 ≥ 30 次以保证统计意义）。

- **命中率 = 命中次数 / 总说命令次数 ≥ 90% → PASS**。
